# Text-only fixed-depth microbenchmarks were presented as Pi speeds; join the real image history and verifier route before promising throughput

Symptom: Pi decoded at roughly 40–52 tokens/s after compaction while a table implied 80 at 64K. The idle dashboard also paired the latest speed with an earlier compaction's larger context.

Cause: the table described another build, text-only requests, fixed depth and 512-token code output. Pi retained screenshot tool results after compaction; those requests disabled the compiled Flash-Next verifier and used adaptive depth and long reasoning. The summary was present and 44 of 45 follow-up requests reused RAM prefixes.

Rule: carry source/build, modality, actual input length, reasoning and depth policy beside speed claims. Include compaction as its own request in God View. Inspect image lineage and route admission before blaming acceptance or cache corruption. Capture system pressure during the request; later snapshots cannot prove historical throttling.
